# 검증과 제한 사항

## 확인한 범위

자동 테스트 모음이나 CI 테스트 설정은 없습니다. 문서 정리에서는 소스·SQL·CSV 구조와 상대 링크를 확인했습니다. 설치·DB 적재·앱 실행·외부 API·브라우저 동작은 실행 검증하지 않았습니다.

## 개발 환경 점검

| 확인 | 기대 결과 |
| --- | --- |
| 적재 후 COUNT | 현재 파일 기준 부품 10·가격 268·연비 506행 |
| 검색·필터 | 존재/부재 모델과 연도·등급 조건; 표시·선택 행 일치 |
| 가격 연결 | `price_model` 유무에 따른 직접 조회/선택 |
| 산식 | 수계산과 연간 합계·월 환산 일치 |
| 전기차 | km/kWh, 고정 단가, 네 부품 제외 |
| API 실패 | 대체 단가의 종류와 표시 확인 |
| 경계값 | 거리 0·음수, 효율 0·NULL, 음수 단가, 교체주기 0 |
| DB 장애 | 연결 실패와 결과 없음 구분 확인 |
| UI | 작은 화면·긴 모델명·키보드·이미지 실패 확인 |

## 현재 구현 한계

1. 검색과 가격 조회에 SQL 문자열 조합을 사용하여 작은따옴표·SQL 주입을 방어하지 않습니다.
2. 적재도 값 문자열을 조합하며 완료 메시지는 입력 건수입니다. 실제 저장 결과를 따로 확인해야 합니다.
3. 수치를 VARCHAR로 저장하고 거리·효율·교체주기의 범위 검증이 부족합니다.
4. 가솔린·디젤 표기가 대체 단가 조건과 다를 수 있고 대체값도 실시간처럼 표시될 수 있습니다.
5. 부품 캐시는 DB 변경을 자동 감지하지 않으며 예상 교체 시기는 실제 정비 이력과 무관합니다.
6. 별도 차량 API의 요청·인증 구성이 소스에 고정되고 비200 응답의 문자열/정수 연결·결과 초기화가 불완전합니다. 예제 import도 현재 정의와 달라 메인 DB 경로와 분리해 점검해야 합니다.
7. 단가·세율·CSV 최신성, 의존성 재현성, 배포·접근성 검증 근거가 부족합니다.

문서 작성 과정에서 소스를 수정하지 않았습니다.
